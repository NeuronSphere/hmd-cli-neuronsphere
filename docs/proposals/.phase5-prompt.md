## Where the work goes

Everything is one function: `execute()` in
src/go/nsctl/internal/nsrunner/exec.go:33, currently a sequential
`for i, node := range nodes`. It was deliberately written as its own loop
(rather than calling runner.Run) so Phase 5 is a change to it alone, with no
change to the HTTP API, the store, or node execution.

`msdeploy.DeploymentNode.Dependencies` is already populated by
ms-deployment and is still read by nothing -- confirm with
`grep -rn "\.Dependencies" internal cmd | grep -v _test`. It is the in-degree
input. The dependencies are repo *instance names*, already transitively
reduced and already filtered to the instances in this changeset.

Targets from SPEC011, taken from the cloud path Argo already runs: default
concurrency 4 (Argo's `spec.parallelism: 4`), overridable per submission.

## Traps

- **Log interleaving is a real problem, not a detail.** Every node writes to
  one `logBuffer` through `runner.Runner.Out`. Four concurrent nodes will
  shred each other's output, and today's log is what `nsctl env start` and
  `env attach` show the user. Decide this deliberately -- per-instance line
  prefixes, or per-node buffers flushed on completion. Sequential-looking
  output from parallel work is probably what a user wants.
- **Fail-fast changes meaning.** Today it returns at the first failure. SPEC011
  wants the context cancelled so no *unstarted* node begins, while in-flight
  nodes finish and report. A node killed mid-deploy leaves half-applied
  Terraform, which is worse than one that completes.
- **`Succeeded` feeds the reconcile snapshot.** apply.go's `settled()` is
  set-based, so ordering is safe -- but it must still contain exactly what
  landed: no more, or a failed entry is skipped next run; no less, or a
  succeeded one redeploys forever. Appending to `run.Succeeded` from several
  goroutines needs a lock; today it is a bare append.
- The core repo class (`hmd-cli-neuronsphere`) executes nothing but still needs
  its status flip and its successors decremented.
- Destroy manifests arrive with edges already reversed. Do not re-reverse.
- A RepoInstance is indivisible: one node, one script, one `hmd deploy`.

## Verification

- `make check` and especially `make test-race` -- this is a concurrency change.
- New unit tests in the house style (stdlib only, hand-rolled fakes on narrow
  interfaces, `t.Parallel()`): a diamond DAG must never start a node before its
  dependency finished, and must run the two independent middle nodes
  concurrently. Assert both, not just the ordering half.
- `bash test/verify-nsrunner.sh` -- standalone, Docker only, ~2 min. Checks the
  workspace mount, failure detail crossing the boundary, the 409 refusal, and
  that a deployment survives its client being killed. It must still pass.
- SPEC011's deliverable is "a cold bootstrap measurably faster than the
  sequential path, with identical outcomes." Measure it rather than asserting
  it, and report the number.
