## Traps

- **There are two version spaces and GoReleaser uses the other one.**
  `make build` injects `main.version` from `meta-data/VERSION`, which is `0.5`
  -- MAJOR.MINOR, no patch. GoReleaser injects `{{ .Version }}` from the git
  tag. This repo's existing tags are BACON pipeline tags (`0.5.202`), not
  `v`-prefixed semver. bartleby carries both spaces and lets them diverge:
  tags `2.1.0.72` and `v2.1.0` while its `meta-data/VERSION` says `1.0`.
  Decide what `nsctl version` prints for a Homebrew install versus a
  `make install`, and put the answer somewhere a user reads.

- **GoReleaser's defaults do not strip, and that is 15 MB.** 34.4 MB with
  `-s -w`, **49.4 MB** without -- so copying bartleby's `.goreleaser.yaml`
  verbatim (it passes only `-X main.version`) ships a binary that meets the
  50 MB target by 0.6 MB instead of 15. Carry `-s -w` across.

- **`windows/amd64` is in SPEC013's list and is probably wrong.** `nsctl`
  shells out to `docker`, mounts `/var/run/docker.sock`, and composes host
  absolute paths that must resolve identically inside sibling containers
  (SPEC010). bartleby ships darwin and linux only. Either make it genuinely
  work or drop it from the SPEC with the reason. Do not publish a target that
  cannot run.

- **`make test-cli` runs a file that does not exist.** The target invokes
  `test/nsctl_cli.robot`; there is no such file. Write it or delete the
  target -- a release pipeline wired to a broken target is worse than one
  wired to nothing.

- **The nsrunner image has no publisher.** `docker-compose.control-plane.yml`
  defaults `HMD_NSRUNNER_IMAGE` to
  `ghcr.io/neuronsphere/hmd-img-nsrunner:stable`, and nothing pushes it --
  which is exactly why the runner is off by default (Phase 4's *Not done*).
  Distribution is this phase. If the image is not published here, that default
  tag is a promise the repo does not keep; either publish it or change the
  default and say so.

- **"The recommended path for new users" is a claim, not a doc edit.**
  SPEC012's parity harness -- a suite parameterised on `hmd neuronsphere`
  versus `nsctl` -- was never built; parity was checked by targeted
  cross-front-end operations. And `nsctl env purge` still does not exist:
  the status table is right about that, and **the Phase 2 entry claiming it
  landed is wrong**. Do not recommend the binary over the Python CLI without
  either closing those or stating plainly what a new user gives up.

  every platform GoReleaser builds, not just the local one.
- `goreleaser build --snapshot --clean` locally: it must produce artifacts
  with no tag and no token. **Do not push a tag and do not trigger a real
  release** -- that is outward-facing and is the user's call.
- Run the install script against the snapshot artifacts, or at minimum
  shellcheck it and exercise its platform detection on darwin/arm64.
- The Homebrew formula cannot be tested without the tap. Assert its shape
  against bartleby's and say plainly that it is untested.
- `git diff --stat` should show docs, repo-root files, and at most
  `cmd/version.go`. Nothing in this phase should change `internal/` behaviour.
